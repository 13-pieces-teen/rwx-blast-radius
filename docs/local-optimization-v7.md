# 本地优化 v7（2026-11-21）

v7 在 30 个公开样例上的本地测量均零漏测，模拟耗时为 **117.861 秒**。
最终镜像连续三轮含 CPU 中位数为 **122.109783 秒**；随后 v6/v7 交错对照的中位数
分别为 **129.369902 / 119.547835 秒**。CPU 出现明显轮次波动，所有记录均保留。
这些是本地结果，不是新的官方成绩。
后续官方实测已完成：提交 `a28c3f2`、回执 `BB-F47DED7A`，**214.4 秒，三轮零漏测**，
较 v6 的 248.4 秒减少 **34.0 秒（13.69%）**。三轮模拟耗时均为 211.977 秒，CPU 为
2.42 / 2.44 / 2.44 秒。页面已选择 v7 作为当前最佳决赛提交。
[官方明细](official-practice-v7-2026-11-21.json)与以下本地测量分开记录。

本轮主要修正隔离补跑引入的依赖膨胀，细化命名空间键存在性读取，加入基于完整
基线观察的比较结果证明，并减少导入检查的解释器启动开销。模块声明、共享类夹具、
冷缓存、源码读取和反射保护继续保留。首次失败、后续对照和历史继承证据分别记录。

## 官方数字与本地目标

旧提交的官方总分 471.7 秒包含一次 300 秒漏测罚时，算术差值
`471.7 - 300 = 171.7` 秒仍包含 CPU；它不是一次实际取得零漏测的有效成绩。
旧版显示的模拟耗时为 468.450 秒，扣罚后纯模拟 CI 开销是 **168.450 秒**。
v6 官方纯模拟 CI 开销为 **245.407 秒**，因此覆盖保护增加了 **76.957 秒**。

官方没有公开旧版漏掉的补丁或隐藏批次的逐补丁成本。本地诊断不能证明这 76.957 秒
具体来自哪些机制，也不能把本地节省量换算成下一次官方分数。当前已确认的线上
改进是 v6 消除了三轮漏测罚时；后续 v7 官方实测又减少 33.430 秒纯模拟 CI，
原先 76.957 秒增量剩余 43.527 秒。该总量变化不能证明各项优化的逐补丁贡献。

## 按原顺序恢复基线依赖

原 warm 图的 TPC-DS 测试因插桩超时，原 cold 图的 generator-memory 测试因内存断言
失败，之前分别用独立进程重跑补图。审计发现，独立补跑会首次导入原测试顺序中已经
加载的 dialect 模块，把模块声明行归为该测试的依赖。以 TSQL `WEEK_OFFSET` 为例，
三份观察均没有内存测试对该字段的实际属性读取，但隔离补跑执行了字段声明行，
使该测试进入一些原本很小的选集。

新工具接受通用 `--target`，完整收集固定基线并核对原测试顺序，执行到目标为止。
它保留原 `nextitem`，避免提前结束类夹具；覆盖追踪只在收集阶段与目标执行时开启，
前面的测试仍实际运行以建立相同模块与缓存状态。生产选择器没有按测试名或补丁名
删除依赖。

| 实际前缀执行 | Passed | Skipped | Subtests passed | 耗时 | 目标 call |
| --- | ---: | ---: | ---: | ---: | ---: |
| cold，执行至 generator-memory | 1225 | 1 | 16185 | 103.00 秒 | 14.728 秒 |
| warm，执行至 optimizer TPC-DS | 1441 | 1 | 22676 | 152.38 秒 | 23.540 秒 |

这是两次成功的**前缀执行**，不描述为两次完整套件通过。恢复直接使用原 warm/cold
raw 图与成功前缀的并集，不再并入旧隔离补跑独有的补充边。原始执行、符号、属性、
模块边以及历史 v4 图、真实收集依赖均保留；既有失败诊断源码读取清理规则不变。

最终相对冻结 v6 删除 14380 条行依赖，其中 memory 为 11904、TPC-DS 为 2476；
删除的属性、符号、模块边也仅属于这两个补跑目标。其他测试删除 0 条边，文件读取
依赖删除 0 条。独立审计分别通过 25 项 memory、25 项 TPC-DS、31 项最终图检查，
证明原 raw、历史图及未知旧并集边均受保留。

采集输出保留原 raw、旧隔离补跑、新前缀三套来源。两次前缀的文件哈希绑定发生在
采集完成后，单独的 `prefix-seal.json` 明确记录 `capture_embedded_hashes: false`，
不宣称采集时已经自带该绑定。恢复同时验证原始文件字节哈希及 CRLF 归一化后与
固定源码清单的一致性。旧 raw 缺少生成器哈希，因此不声称新旧观察器逐字一致；
类夹具包装提前是已知差异。公开重建命令见 [prefix-recovery.md](prefix-recovery.md)。

## 命名空间的键与值

对于普通类的真实内建 `mappingproxy`，精确字符串的 `in/not in` 只观察键是否存在。
当改动仅替换现有字段的纯字面量值、其余 AST 严格不变时，这种读取不依赖字段值。
v2 profile 因此分开记录 `keys`、`fields` 和 `opaque`，并严格核对三类观察与全部读取
之间的一致性；缺模式、缺分类、未知版本或混合版本不能合并。

精度要求接收者元类没有覆盖命名空间查找，而且命名空间内**所有现存键都必须是
精确内建字符串**。独立审计复现了字符串子类键通过自定义相等比较读取派生状态的
反例，因此这种情况继续视为 opaque。`get` 在参数求值后再检查键，覆盖默认参数
注入自定义键的副作用；求值顺序、链式比较短路及原始对象身份保持不变。

最终 namespace 观察已完成 warm、cold 和 eager-import-collection 三模式，收集
1621 个固定测试身份；图有 76 个类的全部读取、245 个字段读取和 41 个类的键读取。
本次基线 opaque catalog 为空不代表自定义对象都可精确处理；相应拒绝逻辑由回归
覆盖。含错误键精度的早期采集未采用，最终来源记录在 `artifacts/namespace-provenance.json`。

## 比较结果的全局证明

新增 profile 只记录未修改基线实际执行的比较操作数和原结果，完成 warm、cold、
eager-import-collection 三种模式。最终包含 1225 个位置，其中 839 个可精确记录；
自定义对象、非布尔结果、异常、过大值、非有限浮点及观察数量超限都会使该位置
变为 opaque。采集时不执行可能的未来改动。

选择器只接受单文件中严格限定的比较操作符或直属纯字面量操作数改动，并要求其余
AST 不变。每个改动位置必须在全部模式、全部测试观察到的操作数上保持原布尔结果；
任何未知或不同结果都会放弃证明。这是跨测试的统一条件，不按个别测试分别宣称
等价，以免共享缓存或派生状态把影响传播给其他测试。源码读取及代码反射读者仍保留。
这里的“全局”指完整基线观察集，不是对任意未来输入的数学等价保证。

## 导入检查 CPU 与未采用方案

每次导入检查使用新的 fork 子进程，父进程只加载标准库检查器，不加载 SQLGlot 或
改动代码。子进程不复用，保留输出抑制、失败处理和 8 秒超时；不支持 fork、父进程
存在其他线程或已加载 SQLGlot/测试框架时回退原 subprocess 路径。

独立 5 组交替 sample A/B 的含子进程 CPU 中位数由 1.765190 秒降至 1.283789 秒；
sample 30 个补丁与历史 142 个补丁的完整 worker 输出保持一致。这是单项实验，
不能与整合镜像的节省量重复相加。任意 Python 导入程序在 fork 与 fresh exec 下
都完全等价的说法不在验证范围内。证据见 `evaluation/round-v7-runtime/`。

同批 142 个既有选集的 worker 排程均达到整数毫秒全局下界，理论可节省 0ms，
因此未增加排程搜索。类创建静态证明原型扫描 1068 个纯字面量字段，0 个通过，
没有收益且已移出生产选择器；不能将该原型描述为已启用的通用安全证明。

## 直接执行、历史继承与诊断证据

**冻结版本直接执行。** 8 个新的比较改动覆盖 8 个文件，种子为 `202611210708`，
候选来自原基线比较观察，并排除历史 142 个补丁触及的比较位置。所有 8 个改动均
选择 0 个测试；其余各 1620 个测试实际执行，合计 **12960 passed、203520 subtests
passed、0 failure、0 timeout**。执行使用冻结 selector `fc9a5d4e…` 和比较图
`7d5c4080…`，与最终整合版本不同；完整哈希和前后未改检查在
`evaluation/round-v7-comparison-probes/summary.json`，不把它表述为最终镜像重新运行了
同样 8 套测试。这些是定向诊断变异，不是无偏随机 benchmark 或隐藏留出集。

**本轮新增省略集合直接执行。** 最终 156 个补丁的集合比较有 37 个收窄。除上述
8 个比较探针与另外 6 个 namespace 新探针外，23 个历史补丁新增省略的 **136 次
测试执行全部通过**，没有失败、超时或收集错误。记录在
`evaluation/round-v7-removed-validation/report.json`。这验证的是相对旧版新增省略
的测试，不等于对这 23 个补丁重新执行了所有省略测试。

**历史证据继承。** 对旧版已经省略的测试，只能在补丁、固定源码和测试身份一致，
且新的省略集合由已通过集合覆盖时继承旧执行证据。必须结合完整选集关系和新增
省略验证，不能只凭测试数量减少或本地 sample 零漏测推定安全。最终集合比较见
`evaluation/round-v7-selection-comparison/report.json`；8 个比较探针的旧验证已直接
覆盖全部 1620 个编号测试，因此其最终省略集合属于该通过集合。
23 个历史改动中另有 13 个未被上一轮 28 份可信继承记录直接覆盖，因此补跑了每项
完整省略集合。12 项首轮通过；最后一项发生一次单测试超时，后续固定条件的原版和
变异对照均通过，详见下一节。13 项成功变异运行累计 **18,820 次测试执行**。
统一证明核对最终实际省略 ID 集合、补丁哈希、固定源码、运行代码与全部工件哈希；
旧版的 28 份记录只按严格集合包含关系继承，不用同名日志或数量近似代替。

**诊断与审核。** 比较证明另有 120 个含操作数副作用和共享缓存的合成程序检查，
2 个接受且结果一致、118 个拒绝且结果变化；它检查已构造的边界，不是通用正确性
证明。命名空间自定义键反例、前缀恢复逐边审计和原型零收益分析分别保存来源，
不混入直接省略测试通过次数。
