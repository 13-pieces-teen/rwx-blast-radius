# Shared process-executor dependencies

The selector now has an additive dependency guard for a process executor that survives across test methods. A failed callable normally fails its own `Future`. Failure while reconstructing an incoming task, reconstructing a returned result or exception, or initializing a worker can instead make the shared executor unusable for later consumers. Line coverage for the later consumers does not include the original reconstruction failure.

`shared_executor_dependencies.py` discovers class-fixture ownership and helper call relationships from pristine test source. The builder additionally runs the complete unchanged suite, records actual submit consumers, and rejects unknown executor factories. An explicit `with ProcessPoolExecutor(...)` has a local lifetime and does not cause a class-wide closure. Same-module and imported-base fixture inheritance are supported. The resulting profile contains source identities, consumer IDs, executed reconstruction lines and the enclosing functions; it contains no mutant IDs, expected failures, or chosen answers.

`tools/build_shared_executor_profile.py` performs the baseline observation. Its inline executor preserves pickle boundaries and the difference between a callable/serialization error and a permanently broken reconstruction/initialization path. This observer is used only to add dependencies. It is not a replacement for native test execution. Ordinary task bodies are not classified as reconstruction dependencies merely because they use the pool.

`SharedExecutorDependencies.expand(patch, selected)` must run after every precision refinement. It adds all consumers of a pool when a patch intersects that pool's reconstruction functions or observed lines. A declaration change in a reconstruction-relevant module also conservatively adds those consumers, because the changed global/class definition need not execute again when read by the decoder. Other function bodies in the same module do not automatically trigger the closure. Missing, stale, invalid or unreadable profiles must cause the production wrapper to retain all tests, rather than disable this guard.

The current profile is 52,818 compressed bytes. It comes from the pinned, unmodified source at `eb11aec4be8cb2122afe713a4816662c3f0fb2fa`: 1,621 collected tests, 1,620 passed, one skipped and 25,440 successful subtests. All parent setup/call/teardown events are retained. The trace found one class-lifetime pool with 22 consumers and two instances of an explicit local-with pool. No unknown factory was observed. Before/after source snapshots are identical. The immutable image, actual CPU/memory limits, source and collector hashes, first class-only run, full-suite run and container cleanup are recorded under `evaluation/shared-executor-dependencies/`; the compact artifact identity is in `artifacts/shared-executor-provenance.json`.

The diagnostic h026 patch is used only after profile generation to validate the fix. The original 176 selected tests expand to 192, including all four previously omitted failing tests. Retaining every pool consumer also adds twelve tests beyond those four; this is deliberate and does not use the failure list to trim the closure. The scheduling cost remains 25.454 seconds for this case.

A read-only comparison against all 806 previously frozen patches quantifies the conservatism. Applied to v8, the guard changes 27 selections and adds 98.037 seconds of aggregate CI cost. Applied to the frozen experimental combined strategy, it changes 37 selections and adds 133.712 seconds. These are aggregate scheduling diagnostics over cohorts with different sampling histories, not CPU measurements or official scores. They do not include penalty changes. The profile was not trimmed to improve these numbers.

Validation includes 21 synthetic unit tests and four production-wrapper integration checks: ordinary task and pickle-write errors remain local; task/result reconstruction and initialization errors invalidate the pool; independent pools remain independent; local-with tasks do not spread across tests; static and dynamic consumers are retained; inherited fixtures are resolved; stale fixture source and unknown factories are rejected; actual default refinement can shrink a result before the final closure restores a necessary consumer; missing/truncated profile files fall back conservatively; and the real h026 selection has the expected retained tests and scheduling cost.

The guard addresses observed process-executor transport dependencies. It does not establish completeness for arbitrary Python global state, new unobserved execution paths, native process termination, or other resource types. Those require separate conservative guards and validation.
