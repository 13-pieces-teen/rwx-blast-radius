# Import-state field profile

`tools.import_state.snapshot(source, overrides, imports)` runs in a fresh process that has not imported SQLGlot. `source` accepts a string or Path. It imports the fixed baseline module order, applies source overrides through a meta-path loader, and emits a dictionary with `fields`, `classes`, `aliases`, `unsupported_fields`, and diagnostic `stats`. Import errors propagate to the caller.

Module fields use `path::name`; class fields use `path:qualname:name`. Records contain `digest`, `kind` (`module` or `class`), `path`, and `name`. Class records additionally contain `qualname`, `class_name`, `defined_on`, and `inherited`. Only defining fields are stored: reader expansion follows `classes[symbol].mro` and `own_fields`, avoiding repeated inherited method records. Synthetic `__bases__` and `__mro__` fields capture inheritance changes. Derived values copied into subclass namespaces are ordinary defining fields.

Values include scalars, containers, enums, regular expressions, function defaults/kwdefaults/closures/annotations, bound methods, partials, properties, descriptors, slots, and SQLGlot expression templates. Direct declared function bodies are left to runtime line coverage. Functions stored in containers, lambdas, and generated closures include bytecode semantics, constants, lexical metadata, and exception tables; code filenames and line-number tables are excluded. Field aliases are folded into each digest, so a caller comparing only field digests observes an equal-value alias split. Immediate aliases within containers are also represented.

The implementation uses stable identities for external modules/classes/functions and loader or synchronization objects. Unknown objects are reported on the containing field; they do not invalidate the entire snapshot. The baseline currently contains no unsupported values. Package paths are relative to the source root. Runtime must use `PYTHONHASHSEED=0`, matching the baseline. Type-keyed dispatch dictionaries are canonically ordered by class module/qualname because class hashes depend on addresses even with a fixed hash seed. Ordinary dictionary insertion order remains part of the digest. Consequently, a type-keyed dictionary's iteration-order-only change is outside this observation contract.

A separate source-based normalization recognizes module fields constructed as `tuple(set literal or constructor)` whose loaded name is used only as the second argument to `isinstance` or `issubclass`, with ordinary class members and no rebinding of those builtins. These membership type sets are sorted while retaining their members. Ordinary tuples, class bases, and MRO remain ordered. The returned `normalization_policy` can be passed back as the optional fourth argument to `snapshot`; unchanged source reuses the baseline policy, while modified policy-owner modules are checked again. Baseline discovery parses only modules containing actual tuples of ordinary types. The policy contains discovered field keys, never mutation identifiers or failure labels.

`diff(before, after)` returns changed records with `key` and `change` (`value`, `added`, or `removed`), class metadata, alias changes, and changed unsupported fields. The production selector combines these observations with field readers and its existing source/reflection/structural/runtime dependencies. A snapshot is not a general proof of filesystem, network, or arbitrary interpreter side-effect equivalence.

The shipped `artifacts/import-state.json.gz` contains the pinned source commit, all 184 SQLGlot source hashes, fixed import order, helper SHA, seed, and stable snapshot. The coverage map separately binds 250 source and test files. `tools/build_import_state_profile.py` seals two independently captured pristine snapshots only after their fields/classes/aliases match exactly and source hashes match `baseline-map.json.gz`. It also checks the immutable image, completed container, no OOM, and successful cleanup. The corresponding provenance file records identities, metrics, and normalization boundaries.

The shipped production-environment evidence is `evaluation/v11/import-state/run-005/`: two fresh Python 3.13.18 processes, production image `sha256:9bdfd6d6284b658dec7913f7b89a1a82c0639f780cc3ed26bbd5c6208e4be1a8`, 2 CPU on cores 0–1 and 3 GiB. Both snapshots contain 183 modules, 1296 classes, 24,775 fields, zero unsupported types, and stable semantic SHA `b55309b544b65e7d0b8113986cfec6cc6e96b6d1120e7c74026fbf88dbd14276`. Import times were 0.249/0.167 seconds, normalization including first-time policy discovery 0.931/0.912 seconds, and process CPU including audit JSON/gzip 1.453/1.408 seconds. These are diagnostic costs, not official scored supervisor CPU measurements; runtime reuses the baseline normalization policy.

Earlier runs remain intact. `run-001` exposed duplicated inherited-field volume and hash-seed variation; `run-002` used compact defining fields and a fixed seed, then identified nondeterministic order in class-keyed maps. `run-003` was stable within the full test-dependency image, but the first candidate run exposed its environment mismatch: production does not install `mypy_extensions`, so the pinned source takes different `i64`, `trait`, and `mypyc_attr` branches. This profile was superseded, not silently retained. `run-004` preserved that old artifact and measured actual production imports; it also revealed one remaining nondeterministic `tuple(set-of-types)` field. The generic type-membership policy resolved that case in `run-005`. Eight synthetic regressions in `tests/test_import_state.py` cover derived values and inheritance metadata, direct function body versus stored lambda/default changes, field and nested aliases, mapping order, generated closures/bound methods, slot/regex stability, and membership-set normalization without sorting ordinary tuples.
